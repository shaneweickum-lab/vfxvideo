1. VISION
===============================================================================

A complete art studio in one application, on one engine:

  - Draw     Procreate-style painting and frame-by-frame animation
  - Photo    image editing: layers, masks, adjustments, retouch
  - Edit     video editing: timeline, cuts, transitions, audio, export
  - Comp     VFX compositing: node graph, keying, roto, tracking

Later, our own AI is added on top of the same engine, as tools inside
these pages (segmentation, matting, upscaling, inpainting, interpolation,
eventually generation).

Guiding rule: master the deterministic craft first. AI arrives only once
the engine, file format, color pipeline and editing tools are solid.

Because this is also an educational project, every stage produces both
working software and written notes explaining how it works (docs/learn/).

===============================================================================
2. THE CORE ARCHITECTURAL IDEA: ONE ENGINE, FOUR PAGES
===============================================================================

Everything is a NODE GRAPH evaluated over TIME. The pages are different
views of the same underlying document.

  - Draw   a stack of paint layers; each paint layer is a node whose
           content is stroke data + raster tiles. An animation is the
           same stack with a different raster per frame.
  - Photo  a graph evaluated at one frame; layers are a linear node stack.
  - Edit   a timeline of clips; each clip owns a small graph.
  - Comp   the full graph exposed to the artist.

Consequences:
  - A brush, blend mode, or blur is written once and works everywhere.
  - An animation drawn in Draw drops straight onto the Edit timeline or
    into a Comp graph as a clip. No export/import step.
  - Projects are non-destructive: source media is never altered.
  - A future AI model is just another node type. No redesign needed.

  +----------------------------------------------------------------+
  |  UI         [ Draw ]  [ Photo ]  [ Edit ]  [ Comp ]               |
  +----------------------------------------------------------------+
  |  DOCUMENT   Project / Layers / Timeline / Graph / Undo / Cmd log  |
  +----------------------------------------------------------------+
  |  ENGINE     Graph evaluator, scheduler, frame + tile caches       |
  +----------------------------------------------------------------+
  |  GPU        WebGPU compute + render (WGSL shaders)                |
  +----------------------------------------------------------------+
  |  MEDIA      WebCodecs decode/encode, image I/O, audio             |
  |  COLOR      scene-linear working space, view transforms           |
  +----------------------------------------------------------------+
  |  STORAGE    OPFS (browser private disk), File System Access API   |
  +----------------------------------------------------------------+

The ENGINE and everything below it must never touch the DOM or UI code.
That rule is what lets us wrap the app natively later without a rewrite.

===============================================================================
3. CAN THIS BE A PWA? (Technology validation)
===============================================================================

Short answer: YES for what we need now. Learning, an internal tool,
drawing, image editing, HD/4K editing of common camera codecs, and 2D
compositing all work. The browser became viable for this in 2025-2026
because these pieces now ship in the browsers we care about:

  - WebGPU     GPU compute and rendering. Chrome on Mac, and Safari 26
               on macOS Tahoe and iPadOS 26 (on by default).
  - WebCodecs  hardware video decode/encode (uses the M5 media engine).
  - OPFS       fast private on-disk storage for caches and projects.
  - Pointer Events with pressure, tilt and coalesced/predicted events,
               which pen drawing needs (Huion on Chrome, Pencil on Safari).

Big bonus of PWA: the SAME app runs on the MacBook, the Chromebook
(with the Huion tablet), and an iPad with Apple Pencil if one is added.

3.1 Honest limits, and how we handle them

  Limit                                Mitigation
  -----------------------------------  ----------------------------------
  Safari lacks WebAssembly 64-bit      Keep big data in GPU textures and
  memory (wasm heap capped ~4 GB).     OPFS, not in the wasm heap. Fine
                                       for our sizes.
  Safari only offers OPFS, not full    Chrome = primary dev browser on Mac
  read/write to user folders.          (full File System Access). Safari
                                       uses import/export + OPFS.
  ProRes / DNxHR / RAW decode is not   Start with H.264, HEVC, AV1, VP9,
  reliably available via WebCodecs.    PNG/JPEG/EXR sequences. Pro codecs
                                       move to the native stage (3.2).
  No OpenColorIO in the browser.       Implement ACES transforms in WGSL;
                                       bake other OCIO configs to 3D LUTs
                                       offline with OCIO's tools.
  Real-time 4K EXR sequences are too   Proxies + disk cache. True 4K EXR
  heavy for the browser.               work is a native-stage goal.
  Browser can evict storage.           Request persistent storage; projects
                                       are always exportable to a file.

3.2 Path to native later (when commercial or pro-codec needs arrive)
  - Wrap the same web app in Tauri (macOS shell, small download).
  - Move hot paths (codecs, EXR, heavy filters) to Rust, compiled both
    to WebAssembly (for the PWA) and native (for the desktop app).
  - Nothing in Stages 0-4 is wasted; the engine/UI split makes this a
    port, not a rewrite.

4. TECHNOLOGY STACK (proposed, needs approval)
===============================================================================

4.1 Language: TypeScript
  Since the team knows neither Rust nor C++, TypeScript is the best
  starting point: the browser is its native home, the learning material
  is enormous, errors are caught by the type checker, and WebGPU's
  shader language (WGSL) is learned alongside it. Rust enters later,
  only where measured performance demands it.

4.2 Tooling
  - Next.js         app framework, used as a static export (no server
                    needed); service worker for install/offline
  - Vitest          unit tests
  - Playwright      browser tests + golden-image (pixel) tests
  - ESLint/Prettier lint and format
  - pnpm            package manager, monorepo workspaces

4.3 UI
  - React (via Next.js) + Tailwind CSS + shadcn/ui components for the
    clean, modern Next.js/Vercel look. Dark theme first.
  - Canvas viewers are our own WebGPU surfaces, never DOM drawing.

4.4 Libraries (open source, license-compatible)
  - mediabunny (or mp4box.js)   read/write MP4/MOV/WebM containers
  - WebCodecs (built-in)        decode/encode video and audio frames
  - Web Audio API (built-in)    audio playback, mixing, sync
  - ffmpeg.wasm                 optional fallback for odd formats (slow)
  - OpenEXR via wasm or a TS    EXR read/write
    EXR reader
  - ACES reference transforms   ported to WGSL
  - OpenTimelineIO format       timeline interchange (JSON, implement
                                reader/writer in TS)
  Every dependency is checked for license before adoption. We avoid
  GPL-only libraries so a commercial option stays open.

4.5 Project license
  Apache-2.0 (decided). Open source, allows commercial use, includes a
  patent grant. See LICENSE.

4.6 AI later
  - Training: Python + PyTorch, offline.
  - In-app inference: ONNX Runtime Web (WebGPU backend), later native.
  - Small, task-specific models first.

5. THE DRAW PAGE (Procreate-style studio)
===============================================================================

5.1 Input
  - Huion tablet (Chrome) and Apple Pencil (Safari) via Pointer Events: pressure, tilt (altitude/azimuth),
    coalesced events for smooth strokes, predicted events for low lag.
  - Palm rejection: ignore touch input while a pen is in contact.
  - Gestures (Procreate conventions): two-finger tap = undo,
    three-finger tap = redo, pinch = zoom/rotate, touch-and-hold =
    eyedropper, quick-shape (hold at end of stroke to straighten).

5.2 Brush engine
  - Stamp-based: a stroke is a series of "dabs" placed along the path.
  - Brush = shape texture + grain texture + spacing, scatter, jitter,
    rotation, pressure/tilt curves, opacity/flow, streamline smoothing.
  - Dabs rendered on the GPU into the layer.
  - Later: wet/smudge mixing, brush import, brush studio editor.

5.3 Canvas
  - Tiled raster (e.g. 256x256 tiles): large canvases, only touched
    tiles use memory, undo stores only changed tiles.
  - Layers, groups, blend modes, opacity, alpha lock, clipping masks,
    reference layers. Shared with the Photo page.
  - Selections and transforms (free, distort, warp). Shared with Photo.
  - Every stroke saved as its raw input samples as well as pixels, which
    enables stroke replay (time-lapse) and, later, AI training data
    (with consent).

5.4 Animation (like Procreate Animation Assist, then beyond)
  - Frame-by-frame: each frame is a layer state; frame strip timeline.
  - Onion skin (frames before/after, color and opacity controls).
  - Frames per second, hold duration per frame, loop / ping-pong / once.
  - Background and foreground (non-animated) layers.
  - Export: GIF, MP4, PNG sequence, animated WebP.
  - Send to Edit timeline or Comp graph as a live clip.
  - Later: keyframed transforms, tweening, audio scrubbing for lip sync.

6. ROADMAP: MASTERY STAGES
===============================================================================

Each stage ends with a measurable gate. We do not move on until it passes.

STAGE 0 - Foundations and Development Debugger
  - Repo, build, CI, PWA shell, test harness, golden-image tests
  - Dev debugger (dev builds only): pixel inspector, GPU memory, timings,
    cache stats, logs, current batch/feature id
  - Image buffers (8-bit, 16-bit float, 32-bit float) on the GPU
  - Color: scene-linear working space, sRGB/Display P3 view transforms
  - Load/save PNG, JPEG, EXR; project save/load to OPFS and to file
  GATE: open an EXR, adjust exposure on the GPU, display on the MacBook's
        P3 screen with correct values matching a CPU reference.

STAGE 1 - Photo: Image Editing
  - Tiled layer system, blend modes, masks, transforms, crop
  - Adjustments: exposure, levels, curves, HSL, white balance, LUTs
  - Selections, undo/redo, export
  GATE: a real retouch job finished in our app, compared side by side
        with an established editor.

STAGE 2 - Edit: Video
  - WebCodecs decode, frame cache, prefetch, proxies
  - Web Audio playback and sync
  - Timeline: tracks, trim/ripple/roll/slip/slide, transitions, titles
  - Per-clip effects (reuse Stage 1 nodes)
  - Export via WebCodecs; OpenTimelineIO import/export
  GATE: cut a 5-minute multi-track 4K H.264/HEVC project on the M5 with
        real-time playback, frame-accurate export, audio in sync.

STAGE 3 - Comp: 2D VFX
  - Node graph editor; merges and correct premultiplication
  - Keying (chroma/difference/luma), spill suppression
  - Rotoscoping (bezier, B-spline, feathering, motion blur)
  - 2D point and planar tracking, stabilization, corner pin
  - Blur/defocus, glow, grain, lens distortion
  GATE: a professional-standard green-screen composite and a screen
        replacement shot.

STAGE 4 - Draw: Painting and Animation
  - Pencil input, brush engine, gestures, streamline
  - Frame-by-frame animation, onion skin, export
  - Draw animations usable as clips in Edit and Comp
  GATE: with the Huion tablet (and Apple Pencil if available), paint an
        illustration and a 2-second looping animation with no
        perceptible input lag.

STAGE 5 - Native and Advanced VFX (only if needed by then)
  - Tauri desktop build, Rust hot paths, pro codecs, full OCIO
  - 3D camera solve, 3D compositing, particles, USD
  GATE: integrate a CG element into tracked live-action footage.

STAGE 6 - AI (after Stages 0-4 gates pass)
  1. Click-to-mask segmentation for roto and selections
  2. Matting / keying refinement
  3. Upscaling and denoising
  4. Frame interpolation (also: in-betweening for Draw animations)
  5. Object removal / inpainting
  6. Generative features
  Prepared from Stage 0: command logs, stroke logs, golden tests, node
  contract, GPU buffers usable as tensors, data provenance records.

7. AI-READINESS REQUIREMENTS (built now, used later)
===============================================================================
  - Every user action is a structured command in a log
    (e.g. {op: "brush.stroke", layer: 3, samples: [...]}).
  - Strokes stored as raw pen samples, not only pixels.
  - Rich metadata per asset (source, color space, timecode, license).
  - Data provenance: we record where every asset came from and whether
    we may train on it. Our AI must be trained only on data we have the
    right to use, including explicit consent from any users.
  - Deterministic rendering so outputs can be compared and evaluated.

9. RISKS
===============================================================================
  - Scope: this is Procreate + Photoshop + Premiere + Nuke. Mitigation:
    strict stage gates; the engine is shared so each stage gets cheaper.
  - Browser memory and performance ceilings. Mitigation: GPU-resident
    data, tiling, proxies, and a planned native path (Stage 5).
  - Safari/WebKit features lag Chrome. Mitigation: test both from day
    one; feature-detect and degrade gracefully.
  - Codec patents (H.264/HEVC) if commercial: we use the OS's hardware
    codecs via WebCodecs, which is the safer route; revisit before sale.
  - AI data rights: provenance from day one.
