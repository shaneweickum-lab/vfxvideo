LEARN 00: HOW THE REPOSITORY IS ORGANIZED
Stage 0, batch B0.1

The big idea
------------
The studio is split into two halves that are kept strictly apart:

  1. The ENGINE (packages/*). Pure TypeScript that knows how to load images,
     run GPU shaders, evaluate the node graph and save projects. It has no
     idea that buttons, menus or React exist.

  2. The APP (apps/web). The Next.js website you see: pages, panels, tool
     buttons. It asks the engine to do things and shows the results.

Why split them? Because the engine is the valuable part. Keeping it free of
UI code means it can later run inside a background worker (so the UI never
freezes), inside a native Mac app, or behind an AI tool, without rewriting it.

How the split is enforced (not just promised)
---------------------------------------------
  - Each engine package's tsconfig.json uses the "WebWorker" library instead
    of "DOM". If engine code touches `document` or `window`, TypeScript
    refuses to compile it.
  - eslint.config.mjs lists which package may import which (the LAYERS
    table). core is the bottom; engine is the top. Importing "upward", or
    importing React into the engine, is a lint error.

What a monorepo is
------------------
One git repository holding several packages that depend on each other.
pnpm "workspaces" link them together locally, so @vfxvideo/core is used by
other packages just like something installed from npm. Turborepo runs a
command (build, test, lint) across every package and caches results, so
unchanged packages are skipped.

What "static export" means
--------------------------
Next.js can run a server, but we do not need one: everything happens in
your browser. `pnpm build` turns the app into plain HTML, CSS and JS files
in apps/web/out/ that any web host can serve, and that can work offline.

Try it
------
  1. Run `pnpm dev` and open http://localhost:3000.
  2. In packages/core/src/index.ts, add:  import React from "react";
  3. Run `pnpm lint`. Read the error. Then remove the line.
